# MapleUp v0.1 產品規格

本文件依原始規劃對話與 repository 中的 v0.1 原型補齊，並非原對話附件的逐字還原。

## 產品目的

回答「現在最該強化哪一隻打王分身？」。以指定 Boss 實戰時間決定是否需要投入，戰力和裝備資料作為輔助。

## 資訊架構

- 強化總覽：待強化、待測試、已停手數量、強化排序、最高戰力摘要、結晶收入摘要。
- 角色管理：角色列表；單一角色分為總覽、能力面板、裝備分析、戰力紀錄。
- 結晶收入：全域呈現角色收入，不在角色頁重複設置收入分頁。
- 設定：停手規則說明、API 狀態、本機示範資料重置。
- 手機版採底部四項導航。

## 判定規則

預設門檻為 30 分鐘。有效指定 Boss 最佳通關時間嚴格小於 30:00 為「停手」；等於或大於 30:00 為「待強化」；無有效時間為「待測」。停手角色退出強化排序。

目前原型的排序分數：
- 停手：0。
- 待測：40。
- 待強化：100 + min(超出門檻秒數 / 10, 60) + 橘色裝備缺口數 × 8。

這是原型排序，不代表投資效益估算。未來應納入成本與預期提升，不能直接把最低戰力或最多缺口視為最高優先。

## 資料與儲存

使用 localStorage，鍵名為 mapleup-v1。資料分為 characters、crystalWeeks、settings；範例見 ../data/schema-example.json，此檔是示例資料，不是 JSON Schema。

角色包含 id、name、job、level、currentPower、maxPower、targetBoss、bestTime、notes、stats、equipment、powerHistory。
- currentPower 保存目前戰力，maxPower 獨立保存歷史最高戰力。
- powerHistory 保存每筆日期及戰力值；目前原型日期採 MM/DD。
- 新增角色時，以輸入戰力初始化目前與最高戰力，非零時新增歷史紀錄。
- 未來同步時，最高戰力只在新值更高時更新，歷史紀錄保留下降的數值。
- equipment 為部位、評等及備註的示範分析。
- crystalWeeks 保存週區間、角色名稱、收入及完成狀態。
- settings.stopUnderMinutes 預設為 30。

## v0.1 已實作

靜態 HTML/CSS/JavaScript，無建置步驟。提供示範資料、頁面切換、角色新增及本機保存、角色四分頁、戰力長條圖及歷史表、角色級別收入表、示範資料重置。

## 原型限制與後續工作

- NEXON API 尚未串接；目前只有狀態與架構說明，沒有同步或排程功能。
- 裝備分析為示範資料，尚未套用完整健檢規則。
- 戰力圖目前為長條圖，時間篩選與正式曲線尚待實作。
- 結晶收入目前彙總所有 crystalWeeks 記錄，未依目前週期過濾；逐 Boss 勾選、編輯及月統計尚待實作。
- 停手門檻目前僅顯示，尚無介面可修改。
- 匯入匯出、備份還原、Excel 匯入、搜尋、編輯與刪除尚待實作。
- 時間解析目前僅驗證數字及冒號格式，尚未限制秒數為 00–59。
- 角色文字直接插入 HTML，正式使用前應加入安全的文字呈現與輸入驗證。
- 正式版規劃 React + TypeScript、serverless 後端及資料庫；API 金鑰應由後端管理。

## 基本驗收目標

29:59 判定停手；30:00 與 30:01 判定待強化；空白時間判定待測。新增角色後重新整理仍可讀取；角色四分頁可切換；首頁不推薦已停手角色繼續投入。
